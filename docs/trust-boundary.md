# Trust boundary

Public PR code runs only on fixed standard GitHub-hosted ubuntu-24.04. No input selects
runner, environment, repository mapping, helper source, command, interpreter, target,
port or production shell. Only exact named workflow_dispatch callers on protected
reviewed public CD main may request operations. Hosted admission must succeed BEFORE
isolated host scheduling; host activation remains UNBOUND in trusted code, not a
caller flag. Publication alone uses a separate fixed reviewed binding and standard
public ubuntu-24.04-arm, never the Oracle host adapter. It rechecks current protected
reviewed main, distinct exact-head approval/ci, fixed accepted app bytes and actual
hosted/native context before its local disposable build daemon. All host operations
still require ACTIVATION and the unchanged rootless wrapper. The isolated public
runner security stage remains separately DEFERRED/NOT_VERIFIED.

Strict stdlib JSON validation and the closed schema reject duplicate/unknown/missing
keys, type substitutions and unsafe command/path/ref/target changes. The named pilot is
the only binding. New projects/resources need separate named authorization plus review.
Secret references are empty; scoped workflow GitHub tokens are never public config.
Checkouts use persist-credentials=false, pinned public helper ancestors and fixed action
SHAs. No pull_request_target, inherited secrets, borrowed credentials, operator store,
Kanban write API, alternate Dispatcher or public PR self-hosted execution is allowed.

Publication provenance binds archive hash/image ID/source/helper/workflow repo and SHA/
run/attempt. Exact-head qualified independent approval, source main ancestry and exact
Actions `ci` evidence remain required, including historical ancestry for rollback.
Build/image, protection, review, merge, environment, deployment, health, rollback and
fresh status are distinct gates. Local fixtures execute stand-ins, not Docker or host
mutations; their positive controls do not attest live infrastructure.

Deploy and rollback use the same noncancelling lock. Stale requests and unknown resources
stop. Update/recovery require authenticated known-healthy receipts and observed exact
image/source/run/attempt. Functional revision is receipt-bound before rollback mutation.
After ambiguous stop/remove inspect once, preserve old/conflicting state and report
nonzero STOP/Incident. Health output projects only fixed nonsecret fields. Original
release failure remains failure even if bounded recovery is healthy.

No new fees; actual platform/runtime limits and independently authorized operation
counts remain. No artificial DevOps lifetime run/PR/push/CI/repair cap is imposed.
Missing permission or capability is a precise dependent-stage stop, not authority to
change accounts, host policy, credentials, mounts, quotas or security mechanisms.
