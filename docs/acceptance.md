## Failed transitions

The failure boundary includes old-container stop/remove. On ambiguous outcomes inspect
once; mutate only the exact owned candidate. Preserve previous/conflicting resources
and emit nonzero sanitized `FAILED_STOP_INCIDENT_REQUIRED` evidence rather than replay.
After completed removal, recovery uses the authenticated previous image AND functional
revision and measures health. Even successful recovery does not make the failed release
successful. Rollback input revision must match its authenticated known-healthy receipt
before image load or mutation. Recovery failure requires native Incident handling by
the authorized controller, never an Actions Kanban mutation.
